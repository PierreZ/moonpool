## Corrections to retained analysis

The retained `docs/references/foundationdb/` sources were enumerated and compared with the current checkout; none of the 27 retained source files was byte-identical to its matched current file. Many current files have moved from `.actor.cpp`/`.actor.h` to coroutine `.cpp`/`.h`; `sim2-file.actor.cpp` has no same-basename current counterpart. Their behavior must not be silently combined across snapshots.

| Retained statement | Verified current behavior |
|---|---|
| Layer 2 says replies use reliable delivery. | `RequestStream::getReply` retains the request; `networkSender` sends replies unreliably. The retained sender source also disproves that analysis. |
| Layer 2 describes a hash-map dynamic registry. | `EndpointMap` is an indexed vector/free list and validates remaining token bits before returning a receiver. |
| Layer 2/3 describes adjustment as adding to one UID word. | `getAdjustedEndpoint` changes an index and high bits in coordination with adjacent registrations; Rust will preserve behavior, not layout. |
| Layer 2 says larger connectionId wins simultaneous connections. | `Peer::onIncomingConnection` uses canonical address ordering, outgoing-idle state and acceptance timing exceptions. |
| Layer 2 specifies CRC32C and length including the header. | `scanPackets` reads payload length and optional 64-bit XXH3 integrity field; checksum is omitted for TLS. |
| Layer 2 claims all local delivery skips serialization. | Local RequestStream delivery can use its queue directly, but transport `sendLocal` uses ObjectWriter and scheduled `deliver`. |
| `lost-response.md` says broken promise leaves the reliable packet queued. | `sendCanceler` cancels retention in its catch path, reports endpoint failure, and rethrows. Its separate permanent-failure branch can wait indefinitely; our approved terminal-stale behavior differs. |
| Retained waitValueOrSignal accepts a Peer but does not race its disconnect future. | Current helper races peer disconnect explicitly; `/fdbrpc/waitValueOrSignal/peerDisconnect` and `/retryOnDisconnect` test the hang fix. |
| Layer 3 orders same DC before same machine and describes latency as smoothed. | Locality ranks SAME_MACHINE=0, SAME_DC=1, DISTANT=2. QueueModel smooths outstanding work; clean latency replaces the prior latency. |
| Retained LoadBalance imports TSS comparison details. | Current `LoadBalanceRequestHooks` isolates application-specific duplication/comparison hooks; generic Rust RPC should do likewise. |
| Nearby JWKS infrastructure implies all public requests enforce tokens. | FlowTransport parses/watches key sets and NetNotifiedQueue calls verify; sampled current GetValue/GetKeyValues request verify methods return true. No complete tenant-token policy is inferred from these call sites. |

The historical Moonpool revision `ed4f3381b28bcad421493abfeaa3997159146143` is not the baseline. The earlier dynamic example at `f3b61d7fc900722ee0999e4ee6ad5e8cf7816838:moonpool-transport/examples/dynamic_endpoint.rs` illustrates address/base-token serialization and multiple instances; its transport, macros, direct Tokio selection and correctness claims are not an implementation base.
